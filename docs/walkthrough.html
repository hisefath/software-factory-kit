software-factory-kit

A software factory where I set intent and approve decisions, agents do the investigating, planning, building and testing, and scripts check the work continuously. Each phase is a single-purpose skill with one declared output. The phase stops when its output is written, and I'm the one who starts the next phase.

The loop

Diamond 1 decides what to build: discover, then define. Diamond 2 decides how: develop, then deliver. Spec-driven development fits on top of the diamonds: AGENTS.md plays the role of the constitution, followed by specify, clarify, plan, tasks, implement and validate. from Double Diamondfrom spec-kit

The questions I answer

G1 · PRD
Right problem, scope, non-goals and success measure, with every ⚠ resolved or waived?
G2 · HLD
Do these containers, connections, trust boundaries and invariants match my intent? Approve D<n>?
G3 · LLD
Could I defend every table, state owner, endpoint and sequence in an interview?
G5 · Merge
Is the evidence pasted, every disposition done, nothing graded its own work, and can one revert roll it back?

Answers are Approve / Revise / Stop. My exact words go into .handoff/TRACKER.md with the artifact's commit SHA before anything acts on them. If the file changes after that SHA, the approval is stale. mine: SHA-bound approvals

Tracks

Not every change needs every gate.

Fix

Fits in one sentence, touches ≤2 files, has a repro, and changes no API, data model, dependency, auth, payment or migration. Runs fix-bug → verifier → G5.

Standard

The next milestone of a product that already has a PRD. Runs the LLD delta → diagrams → G3 → acceptance → tasks → G4 → build → G5.

Full

A new product or graded project. Every phase, and each planning phase is its own merged milestone: M1 research → M2 PRD → M3 design → smaller implementation milestones. mine

Dispatch: who does what

My rule: the Claude supervisor hands a job to another harness or a subagent only when the job is one skill, isolated (it owns its own files and needs files, not conversation) and parallel (something else can run at the same time). The best example is diagrams: once the architect's design is written, Codex draws the ERD, class diagrams, component tree and sequence diagrams side by side. mine

How to use it

  1. Scaffold a project. Then fill in the Commands table in AGENTS.md and copy Makefile.example to a real make check.
    bash ~/Desktop/gauntlet_workbench/software-factory-kit/scripts/init-repo.sh ~/Desktop/gauntlet_workbench/my-project
  2. Open Claude Code in the repo. The SessionStart hook prints the Resume block. Describe what you want in plain words; the supervisor picks a track, adds a tracker row and tells you the next command.
  3. Decode the prompt first. Type /decode-prompt. It finds what the project is really testing (the question behind the question) and the traps a one-shot build would fall into, with a guard for each, then stops at G-decode.
  4. Plan, one phase at a time. Type /sharpen-brief. It asks one question at a time, each with a recommended answer, then stops at G0. Answer Approve / Revise / Stop, and the supervisor records your words and runs log-decision. Do the same with /write-prd (G1), /design-hld (G2) and /design-lld (G3).
  5. Let diagrams fan out. After each design draft, the supervisor commits it, dispatches one draw-diagrams job per diagram type, then embeds the results:
    bash scripts/embed-diagrams.sh docs/architecture/lld.md
  6. Define done, then slice. /define-acceptance writes red tests. /slice-tasks writes one file per task and prints a coverage matrix for G4.
  7. Build. Say "go M2". Tasks whose files don't overlap run in parallel, each in its own worktree. The supervisor checks every result itself: the result file, then scope-guard, then make check, then the diff.
  8. Close the milestone. Run /garden-docs, then the verifier alongside /check-security, then /report-milestone → G5. You merge; then /ship-milestone.
  9. Improve the factory. /route-failure turns each failure into a FINDINGS row and a proposed fix in the right layer. /quiz-me gets you interview-ready. /write-demo-script (Codex) and then /record-demo handle the video.

Verification

Automated quality gates

  • scope-guard.sh: fails any change outside the task's Owns: paths. It reads the scope from the base branch, so a task can't widen its own scope.
  • make check: lint, types and tests in one green/red command.
  • pre-push: both of the above, plus a secret scan.
  • Red acceptance tests written before any code exists.

Separation of duties

  • The verifier can read but not edit.
  • The verifier never sees the worker's own summary.
  • The supervisor re-runs the checks itself; an exit code isn't proof.
  • Implementers can never edit tests/acceptance/**. from Proof Loop

Failure routing

When an agent fails, fix the narrowest layer that would have stopped it. Fix tools and the environment before rewording prompts. Nothing new is added without a FINDINGS row. from compound engineering

SymptomFix it in
Checkable behavior brokea failing test first
Wrote outside its phase or taskOwns: + scope-guard (code, not words)
Built the wrong thingthe spec: sharper requirements, a new brief question
Same wrong command againone line in AGENTS.md, or a script
Phase procedure botchedthat skill's recipe + red-flags row
Wrong skill firedthe skill description's "Do NOT use for…"
Plugin hijacked the sessionsettings: turn it off per repo (F1)
One-off quirklog it; don't make it a rule
